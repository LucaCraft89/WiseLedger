**Team Coin³** · *Agentic Dollars on Bitcoin* hackathon, BLOX Turin, 17–18 October 2026

> A local AI that reads your invoices, catches the fraudulent ones, and pays the good ones with RGB assets on Bitcoin, from your own self-custodial wallet. Nothing leaves your device.

## The idea
Invoice fraud (changed bank details, fake suppliers, duplicate invoices, instructions hidden inside a document) is a real loss for freelancers, small firms and accountants, and paying in digital dollars makes a wrong payment irreversible. WiseLedger puts a private, on-device checkpoint between an invoice and the money:

1. **Upload an invoice** (PDF, image, text, Italian FatturaPA XML).
2. **Analyst** (a local QVAC model) extracts the data and runs safety checks: valid RGB invoice, right asset, amount matches the lines, duplicates, new payee, pressure language, prompt injection. Deterministic rules decide the verdict (ok / review / block); the model only explains it in plain language and never sees the raw invoice text when it writes the explanation.
3. **You confirm** a sentence generated by code from the exact payment ("Pay 25.00 TUSDT to Acme Srl, now").
4. **Treasurer** (a second local QVAC agent) executes the payment with RGB, now or scheduled, through a guard that only lets a confirmed plan move funds. It also labels transfers, creates receive invoices and produces a fiscal report.

## How to run
**Prerequisites:** Linux x64/arm64 or Apple Silicon (on Windows: WSL2 Ubuntu 24.04), glibc ≥ 2.38, **Node 22.x** (the rgb-lib binding does not build on Node 24+), pnpm, about 4 GB free RAM for the 2B model. Docker only for the offline regtest.

```bash
git clone https://github.com/LucaCraft89/WiseLedger && cd WiseLedger
nvm use                      # Node 22
pnpm install
pnpm check                   # typecheck, lint, tests, secret scan
pnpm demo:mock               # whole flow on mocks: paid, reviewed, blocked (no AI, no chain)
cp .env.example .env         # then set WALLET_BACKEND=wdk-rgb, LLM_PROVIDER=qvac
pnpm wallet:smoke            # creates payer + payee test wallets, prints funding addresses
# fund both on https://faucet.mutinynet.com, then:
pnpm -F wallet issue-asset   # issues TUSDT; put the asset ID in .env as ASSET_ALLOWLIST
pnpm demo:prepare            # fresh RGB invoices + 4 demo invoice PDFs in .data/demo/
pnpm -F wallet payee watch & pnpm dev   # supplier side + server and web → http://localhost:5173
```
Upload `.data/demo/1-good-acme.pdf`, read the Analyst's report, confirm the sentence, watch the RGB transfer settle (explorer link). Then upload the scam, duplicate and injection invoices: each is blocked with a plain reason.

| Env | Values | Meaning |
|---|---|---|
| `LLM_PROVIDER` | `qvac` · `openai` · `mock` | on-device QVAC; `openai` = a local `qvac serve --openai`; `mock` = scripted |
| `WALLET_BACKEND` | `wdk-rgb` · `mock` | real RGB wallet on WDK, or in memory |
| `RGB_NETWORK` | `mutinynet` · `regtest` | test networks only |
| `PAYMENT_CAP` | base units (`100000000` = 100 TUSDT) | max per payment, enforced by WDK policy and the guard |
| `ASSET_ALLOWLIST` | asset IDs | assets you accept to pay with |

Chain details, troubleshooting and the offline regtest: [`infra/RUNBOOK-chain.md`](infra/RUNBOOK-chain.md). Wallet env: [`packages/wallet/README.md`](packages/wallet/README.md).

## Built during the hackathon (so far)
- Wallet on WDK + `@utexo/wdk-wallet-rgb`: seed handling, TUSDT issuance, blind receive invoices (fixed or open amount), RGB payments with explicit fee rate, transfer tracking, background sync. First real transfer on Mutinynet: [5 TUSDT, settled in 57 s](https://mutinynet.com/tx/c079929a2ebda5c5b025a953b77d9c0d03b5a56a47b87c020c02d8744a453b0b); first invoice paid through the app: [25 TUSDT](https://mutinynet.com/tx/c9607b67acae9cdbe6c4ae9e8ea7a2fa6b48a6d7dd07f91f08c143ca8c4e0cfc).
- **WDK spend policies on the RGB account** (max per payment, asset allowlist), refused before signing.
- **PaymentGuard**: a payment moves only for a plan a human confirmed, unchanged (hash), under the limits, with funds, exactly once (idempotency survives restarts); a send timeout is never retried.
- Analyst on QVAC (structured extraction, deterministic rules, summary that never sees the invoice text), Treasurer on QVAC tool calling, server with crash-safe invoice states, web UI with streaming analysis and plain-language flags.
